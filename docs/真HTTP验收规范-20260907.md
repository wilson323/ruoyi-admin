### 1.2 W1-W6 现状(治理摸底)

| 维度 | 现状 | 问题 |
|---|---|---|

### 1.3 战略转向

**严格区分两类测试**,各有边界:

| 类型 | Mock 策略 | 验证目标 |
|---|---|---|
| **纯逻辑测试** | 允许 Mock | 纯函数 / parser / 状态机 / 静态契约扫描 |
| **业务测试** | **禁止 Mock** | 端点契约 / 业务流 / 跨 API 工作流 / 权限 gating |

两类测试**不互斥** — 同一业务可分别有"纯逻辑"和"业务"两个测试文件。命名约定:`<scope>.live.test.ts` 表示业务测试,`<scope>.test.ts` 表示纯逻辑测试。

## 二、两类测试的判定

### 2.1 纯逻辑测试(允许 Mock)

**判定原则**:测试运行结果**不依赖后端返回字段值**,只依赖代码本身的处理逻辑。

**适用清单**:

1. **状态机** — `apps/web-antd/src/views/ipd/_shared/ipd-state-machines.ts` 及其测试
   - 例:`canTransition(fromState, toState)` 不连后端就能验证
2. **parser / normalizer / validator** — `apps/web-antd/src/api/ipd/portal.ts` `parseSubmitted` 等
   - 例:8 位查询码正则 `^[A-Z0-9]{8}$` 不需要真后端
3. **静态契约扫描** — `apps/web-antd/src/views/ipd/_shared/ipd-permission-codes.test.ts`
   - 例:遍历 views/ipd + router 验证权限码字面值出现(fs 递归,**不连 HTTP**)
4. **纯函数工具** — `format`、`ipd-error-text`、`use-focus-trap`、`use-filter-sync`
   - 例:`ipdErrorText(error)` 接受任意 error 对象,不需要后端
5. **不依赖后端数据的 UI 渲染分支**
   - 例:`Alert` 文案在不同 status 下的显隐(只要 props 传入正确,Mock store 即可)

**Mock 策略**:
- `vi.mock('api/ipd/<module>')` 替换导出函数
- `vi.stubGlobal('fetch', mockFetch)` 拦截 HTTP
- happy-dom 渲染组件,断言 DOM / Pinia store / 路由跳转

### 2.2 业务测试(必须真 HTTP 真 DB)

**判定原则**:测试运行结果**必须依赖后端实际响应**,Mock 会导致业务风险静默通过。

**适用清单**:

1. **API 端点契约** — request body 白名单 / response envelope 解析
   - 例:`login -> IpdRequestError` 中 `error.message === IPD_LOGIN_CREDENTIAL_TEXT` 必须真发 `/auth/login` 验 401+code=10001
2. **业务流端到端** — login → list → action → state change
   - 例:访客提交需求 → 后端入库 → 用 8 位查询码查回状态变更(必须真 DB)
3. **跨 API 工作流**
   - 例:`refreshIdentity` 后 access 过期 → 自动续期 → sessionStorage 更新(必须真 Java access TTL)
4. **权限 gating(真实 403 响应)**
   - 例:无权限用户访问 `deletion/review` 应得 403 而非 200 mock(必须真后端 SaToken)

**Mock 策略**:
- `vi.stubGlobal('fetch', networkFetch)` 但 `networkFetch` 是 **真 node:http fetch**(见 §3)
- fixture 文件提供 persona 凭据
- 测试输出 verification JSON 到 `/Users/mac/.../frontend/auth/refresh/`

## 三、`_shared/test-helpers/live-http.ts` API

> 本模块由 **A31** 在 W7 创建,封装 pioneer 模式(`auth-live.test.ts` L31-L53)的公共设施。

### 3.1 模块位置与导入

```
apps/web-antd/src/views/ipd/_shared/test-helpers/live-http.ts
```

```ts
import {
  loadPersonaFixture,
  installLiveFetch,
  liveModeEnabled,
  liveGateDescribe,
  getLiveHttpEvents,
  clearLiveHttpEvents,
  type PersonaFixture,
  type LiveHttpEvent,
} from '@views/ipd/_shared/test-helpers/live-http';
```

### 3.2 导出清单

#### 类型

##### `PersonaFixture`
```ts
interface PersonaFixture {
  personId: string;        // '900103' 等
  username: string;        // 'ipd-market' 等
  currentPassword: string; // 已设置的当前口令
  phase: 'VERIFIED';       // 必须 VERIFIED
  scope: 'FULL';           // 必须 FULL
  mustChangePwd: false;    // 必须 false(测试不改口令)
}
```

##### `LiveHttpEvent`
```ts
interface LiveHttpEvent {
  path: string;            // '/api/v1/auth/login' 等
  http: number;            // 200 / 401 / 403 ...
  code: number;            // 后端业务码 0 / 10001 / 20001 ...
  envelopeComplete: boolean; // payload 包含 code/message/data/timestamp/traceId 全字段
  at: string;              // ISO 时间戳
}
```

#### 函数

##### `loadPersonaFixture(personId: '900103'): PersonaFixture`
- 从 `/Users/mac/Documents/ruoyi-ai/.codex/ruflo/swarm-20260905-decisions/frontend/auth/private/<username>.json` 读取
- **强制校验**:
  1. `statSync(path).mode & 0o777 === 0o600`(权限)
  2. `phase === 'VERIFIED'`
  3. `scope === 'FULL'`
  4. `mustChangePwd === false`
  5. `personId` 与调用参数一致
- 任一校验失败 → 抛 `Error`,测试 fail-fast

##### `installLiveFetch(endpointAllowlist: readonly string[]): { nativeFetch: typeof fetch }`
- `vi.stubGlobal('fetch', networkFetch)` 接管 fetch
- `networkFetch` 行为:
  1. 检查 `String(input)` 是否在 `endpointAllowlist` 中
  2. **不在白名单** → 抛 `Error('Live test refuses any other endpoint')`(pioneer L45)
  3. 在白名单 → `nativeFetch('http://127.0.0.1:15666' + path)` 真发 HTTP
  4. 解析响应 → push `LiveHttpEvent` 到全局 events 数组
  5. 返回原 Response 给调用方
- `nativeFetch` 用 `node:http.request` + 5s timeout 实现(同 pioneer L31-L41)

##### `liveModeEnabled(): boolean`
- 读取 `process.env.IPD_LIVE_ACCEPTANCE`
- 当前接受值:
  - `'market-900103-existing-password'` — 用现成口令真登入真退出
  - `'market-900103-natural-expiry'` — 等自然过期后 refresh 续期
- 其它值 / 未设置 → `false`

##### `liveGateDescribe(name: string, fn: () => void): void`
- 等价于 `describe.skipIf(!liveModeEnabled())(name, fn)`
- 包装业务测试 describe 块,**未启用 live mode 时自动 skip**(不影响本地纯逻辑开发)

##### `getLiveHttpEvents(): readonly LiveHttpEvent[]`
- 返回已收集的全部事件(只读副本)

##### `clearLiveHttpEvents(): void`
- 清空全局 events 数组(用于 `beforeEach` 重置)

### 3.3 设计取舍

- **白名单而非黑名单**:防止业务测试"跑飞"访问未授权端点(pioneer L45 已示范)
- **events 全局数组**:便于 `finally` 块统一写 verification JSON(pioneer L115)
- **`describe.skipIf` 而非 `describe.only`**:本地默认不跑 live,需要显式设 env 跑 — 与 CI 化(§5)对齐
- **`nativeFetch` 暴露**:保留给测试用例自定义 header(如 `Authorization: Bearer ...` revoked token 验证)

## 七、不可豁免的边界

### 7.1 测试**不允许**

- ❌ **跳过 fixture 权限校验** — `loadPersonaFixture` 不接受"先加载再跳过 mode 检查"的入口;一旦跳过,等同于口令明文落 git
- ❌ **改 fixture 文件 mode** — `chmod` 或 `git update-index` 修改 `private/*.json` 权限位即 fail test
- ❌ **改 `mustChangePwd` 测试** — 业务测试**永不允许**触发 change-password 端点;pioneer 文件头注释已固化此约束(L1)
- ❌ **用 `vi.mock` 替换 `installLiveFetch`** — live test 必须用真 node:http fetch;mock fetch 等于绕过规范
- ❌ **扩展 endpoint allowlist 到非业务流端点** — 仅允许业务流端点(`/api/v1/auth/*` 是 starter set,后续业务按需追加)

### 7.2 测试**允许**

- ✅ **新增 fixture personas**(后续 PR) — RD_PM / GROUP_LEADER / SUPER_ADMIN 按 §4.4 规范追加

## 八、已知问题

> 落仓:2026-09-07
> 来源:W7 收口期间 A33 `portal-live.test.ts` 真 HTTP 跑出 fixture drift
> 性质:已知问题登记 + owner 解决路径(短期 known issue,长期 owner-decided)
> 状态:**OPEN** — owner 决策点,默认 mode 守住 856 passed + 14 skipped 门槛

### 8.1 现象

W7 收口时,A33 `apps/web-antd/src/views/ipd/portal/portal-live.test.ts` 真 HTTP 跑出以下分裂结果:

| 步骤 | 操作 | 结果 | 备注 |
|---|---|---|---|
| 1 | login | **FAIL** | `400+code=10001 "用户名或密码错误"` |
| 2 | submit(匿名 `/api/v1/public/demands`) | **PASS** | 真 DB 写入成功 |
| 3 | track(query code `CM1BSE20`) | **PASS** | 真 DB 读回状态变更 |
| 4 | audit | **FAIL** | 阻塞于步骤 1 的 login session 缺失 |
| 5 | logout | **FAIL** | 阻塞于步骤 1 的 login session 缺失 |

**根因**:`market-current.json` 的 `currentPassword` 字段被前 wave 旋转,不再与后端 DB `persons.password_hash` 匹配 — 凭据校验第一步就 fail,后续依赖 session 的步骤全部级联失败。

### 8.2 复现命令

```bash
IPD_LIVE_ACCEPTANCE=market-900103-existing-password \
  pnpm exec vitest run --config vitest.ipd.config.mts \
  apps/web-antd/src/views/ipd/portal/portal-live.test.ts --reporter=default
```

预期 **3 failed / 2 passed** — 与上表步骤 1/2/3/4/5 对应。

辅助验证(绕过前端,直击后端):

```bash
# 1. 验证密码确实错(正确 envelope 响应,排除网络层)
curl -X POST http://127.0.0.1:16039/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"ipd-market","password":"WRONG"}'
# → {"code":10001,"message":"用户名或密码错误",...}

# 2. 确认无 admin 端点可重置
curl http://127.0.0.1:16039/api/v1/admin/persons
# → {"code":404,"msg":"No endpoint GET /api/v1/admin/persons."}

# 3. 确认 change-password 需要先登录(鸡生蛋)
curl -X POST http://127.0.0.1:16039/api/v1/auth/change-password \
  -H 'Content-Type: application/json' \
  -d '{}'
# → {"code":20001,"message":"未认证或凭证失效",...}
```

### 8.3 根因分析

- **fixture 旋转的源头**:`apps/web-antd/src/views/ipd/auth/auth-live.test.ts` 现有 skipped live test 注释中提到的 "optional natural access expiry" 路径(等登录后 access token 自然过期,然后 refresh 续期)— 该路径下后端数据库的密码被业务测试触发修改,但 fixture JSON 没同步更新
- **fixture 与 DB 脱节**:`loadPersonaFixture` 只校验 file mode / phase / scope / mustChangePwd / personId 五项(§3.2),**不校验口令与后端 DB `persons.password_hash` 的一致性** — 这是规范层面的盲区,见 §8.6
- **无 admin API**:`/api/v1/admin/persons` 返回 404,前端没有重置路径
- **无 DB 凭证**:后端 PID 65576 running on 127.0.0.1:16039,但 DB 用户/密码只在后端会话可见,前端 owner 不可直连
- **change-password 需要 session**:鸡生蛋 — 必须先登录才能改密码,但当前 password 已经错
