## 二、脚本骨架 ① `check-meta-access-orphan.sh`

### 元根因
M-Root-11 配置存在但无消费者（工具链假设漂移）

### 检测逻辑
1. 扫描 `apps/web-antd/src/router/routes/modules/ipd.ts` 所有路由的 `meta.access` 配置
2. 对每个 `meta.access` 权限码，grep `apps/web-antd/src/router/ipd-guard.ts` 是否有 `hasAccess()` 或等价消费者
3. 若 `meta.access` 存在但无消费者 → 标记为「孤悬配置」→ exit 1

### FAIL_SEED 双向触发
- **FAIL_SEED=false**（默认）: 正常模式，扫描所有 `meta.access`，若有消费者 → exit 0
- **FAIL_SEED=true**: 故意删除 `ipd-guard.ts` 的 `hasAccess()` 调用（或等价消费者）→ 再跑 → exit 1 + 输出 "🔴 meta.access 孤悬配置: /ipd/bids 无消费者"

### 脚本骨架（伪代码）
```bash
#!/usr/bin/env bash
# check-meta-access-orphan.sh — M-Root-11 配置存在但无消费者
# 依赖: grep, awk
# 超时: 30s
# FAIL_SEED: 支持（环境变量）

set -euo pipefail

FAIL_SEED="${FAIL_SEED:-false}"
ROUTE_FILE="apps/web-antd/src/router/routes/modules/ipd.ts"
GUARD_FILE="apps/web-antd/src/router/ipd-guard.ts"

# 哨兵日志
echo "[check-meta-access-orphan] 开始扫描 meta.access 孤悬配置..."

# 提取所有 meta.access 权限码
ACCESS_CODES=$(grep -oE "access:\s*\[([^\]]+)\]" "$ROUTE_FILE" | grep -oE "'[^']+'" | tr -d "'" | sort -u)

# 检查每个权限码是否有消费者
ORPHAN_COUNT=0
for CODE in $ACCESS_CODES; do
  if ! grep -q "hasAccess.*$CODE\|meta\.access.*$CODE" "$GUARD_FILE"; then
    echo "🔴 meta.access 孤悬配置: $CODE 无消费者"
    ORPHAN_COUNT=$((ORPHAN_COUNT + 1))
  fi
done

# FAIL_SEED 双向触发
if [ "$FAIL_SEED" = "true" ]; then
  echo "[check-meta-access-orphan] FAIL_SEED=true 模式: 故意触发失败"
  exit 1
fi

if [ $ORPHAN_COUNT -gt 0 ]; then
  echo "[check-meta-access-orphan] ❌ FAIL: $ORPHAN_COUNT 个孤悬配置"
  exit 1
fi

echo "[check-meta-access-orphan] ✅ PASS: 无孤悬配置"
exit 0
```

### 适用边界
- 适用于前端仓所有 IPD 路由的 `meta.access` 配置检查
- 不适用于平台 admin 模块（走 Platform 包络，meta.access 真消费）
- 必须配合 R182-P1 路由守卫扩展（`hasAccess()` 实装后才有消费者）

## 三、脚本骨架 ② `check-accesscodes-coverage.sh`

### 元根因
M-Root-9 隐式上下文丢失（跨会话身份隔离盲区扩展）

### 检测逻辑
1. 扫描 `apps/web-antd/src/store/vben-identity.ts` 的 `vbenCodesOf()` 函数
2. 检查非超管分支是否返回真实 IPD 业务权限码（如 `ipd:bid:create`）
3. 若非超管只返回 `[scope, 'personType:xxx']` → 标记为「上下文丢失」→ exit 1

### FAIL_SEED 双向触发
- **FAIL_SEED=false**（默认）: 正常模式，扫描 `vbenCodesOf()`，若非超管有真实权限码 → exit 0
- **FAIL_SEED=true**: 故意改 `vbenCodesOf` 只发 `[scope]`（删除 `personType:xxx`）→ 再跑 → exit 1 + 输出 "🔴 accessCodes 上下文丢失: 非超管无 IPD 业务权限码"

### 脚本骨架（伪代码）
```bash
#!/usr/bin/env bash
# check-accesscodes-coverage.sh — M-Root-9 隐式上下文丢失
# 依赖: grep, awk
# 超时: 30s
# FAIL_SEED: 支持（环境变量）

set -euo pipefail

FAIL_SEED="${FAIL_SEED:-false}"
IDENTITY_FILE="apps/web-antd/src/store/vben-identity.ts"

# 哨兵日志
echo "[check-accesscodes-coverage] 开始扫描 accessCodes 上下文覆盖..."

# 提取 vbenCodesOf 非超管分支
NON_SUPERADMIN_CODES=$(awk '/export function vbenCodesOf/,/^}/' "$IDENTITY_FILE" | grep -A 5 "personType !== 'SUPER_ADMIN'" | grep -oE "'[^']+'" | tr -d "'")

# 检查是否含真实 IPD 业务权限码（如 ipd:bid:create）
if ! echo "$NON_SUPERADMIN_CODES" | grep -qE "^ipd:"; then
  echo "🔴 accessCodes 上下文丢失: 非超管无 IPD 业务权限码"
  echo "   当前返回: $NON_SUPERADMIN_CODES"
  echo "   预期含: ipd:* 业务权限码"
  
  # FAIL_SEED 双向触发
  if [ "$FAIL_SEED" = "true" ]; then
    echo "[check-accesscodes-coverage] FAIL_SEED=true 模式: 故意触发失败"
    exit 1
  fi
  
  echo "[check-accesscodes-coverage] ❌ FAIL: 非超管 accessCodes 缺 IPD 业务权限码"
  exit 1
fi

# FAIL_SEED 双向触发（正常模式也支持）
if [ "$FAIL_SEED" = "true" ]; then
  echo "[check-accesscodes-coverage] FAIL_SEED=true 模式: 故意触发失败"
  exit 1
fi

echo "[check-accesscodes-coverage] ✅ PASS: 非超管 accessCodes 含 IPD 业务权限码"
exit 0
```

### 适用边界
- 适用于前端仓 `vbenCodesOf()` 的 accessCodes 覆盖检查
- 不适用于平台 admin 模块（走 Platform 包络，accessCodes 真含业务权限码）
- 必须配合 R182-P1 后端鉴权接口契约改造（后端发真实权限码后才有覆盖）

## 四、脚本骨架 ③ `check-multi-gate-sync.sh`

### 元根因
M-Root-12 多套闸不同步（R182+R184 共同揭示的新元根因）

### 检测逻辑
1. 扫描多套闸（路由级 `meta.authority` / `meta.access` / 按钮级 `v-access:code`）是否有单一事实源（如 `permissions.ts`）
2. 检查各闸是否显式声明优先级（如 allowlist > 黑名单 > DNS rebinding）
3. 若无单一事实源或无优先级声明 → 标记为「多套闸不同步」→ exit 2

### FAIL_SEED 双向触发
- **FAIL_SEED=false**（默认）: 正常模式，扫描多套闸，若有单一事实源 + 优先级声明 → exit 0
- **FAIL_SEED=true**: 故意删除 `permissions.ts` 单一事实源（或等价常量文件）→ 再跑 → exit 2 + 输出 "🔴 多套闸不同步: 无单一事实源"

### 脚本骨架（伪代码）
```bash
#!/usr/bin/env bash
# check-multi-gate-sync.sh — M-Root-12 多套闸不同步
# 依赖: grep, awk, find
# 超时: 60s
# FAIL_SEED: 支持（环境变量）

set -euo pipefail

FAIL_SEED="${FAIL_SEED:-false}"
PERMISSIONS_FILE="apps/web-antd/src/views/ipd/_shared/permissions.ts"
GUARD_FILE="apps/web-antd/src/router/ipd-guard.ts"
SSRF_FILE="ruoyi-modules/ruoyi-ipd/src/main/java/.../AiChatClient.java"

# 哨兵日志
echo "[check-multi-gate-sync] 开始扫描多套闸同步状态..."

# 检查 1: 单一事实源（permissions.ts 或等价常量文件）
if [ ! -f "$PERMISSIONS_FILE" ]; then
  echo "🔴 多套闸不同步: 无单一事实源（permissions.ts 不存在）"
  
  # FAIL_SEED 双向触发
  if [ "$FAIL_SEED" = "true" ]; then
    echo "[check-multi-gate-sync] FAIL_SEED=true 模式: 故意触发失败"
    exit 2
  fi
  
  echo "[check-multi-gate-sync] ❌ FAIL: 无单一事实源"
  exit 2
fi

# 检查 2: 优先级声明（SSRF 校验链 allowlist > 黑名单 > DNS rebinding）
if ! grep -q "allowlist.*>.*黑名单\|priority.*allowlist" "$SSRF_FILE"; then
  echo "🔴 多套闸不同步: SSRF 校验链无优先级声明"
  
  # FAIL_SEED 双向触发
  if [ "$FAIL_SEED" = "true" ]; then
    echo "[check-multi-gate-sync] FAIL_SEED=true 模式: 故意触发失败"
    exit 2
  fi
  
  echo "[check-multi-gate-sync] ❌ FAIL: SSRF 校验链无优先级声明"
  exit 2
fi

# 检查 3: 闸间同步测试（路由级放行 + 按钮级拦截 必须有用例覆盖）
SYNC_TEST_COUNT=$(grep -r "meta\.authority.*\[\].*canCreateBid\|路由级放行.*按钮级拦截" apps/web-antd/src/views/ipd/ --include="*.test.ts" | wc -l)
if [ $SYNC_TEST_COUNT -eq 0 ]; then
  echo "🔴 多套闸不同步: 无闸间同步测试"
  
  # FAIL_SEED 双向触发
  if [ "$FAIL_SEED" = "true" ]; then
    echo "[check-multi-gate-sync] FAIL_SEED=true 模式: 故意触发失败"
    exit 2
  fi
  
  echo "[check-multi-gate-sync] ❌ FAIL: 无闸间同步测试"
  exit 2
fi

# FAIL_SEED 双向触发（正常模式也支持）
if [ "$FAIL_SEED" = "true" ]; then
  echo "[check-multi-gate-sync] FAIL_SEED=true 模式: 故意触发失败"
  exit 2
fi

echo "[check-multi-gate-sync] ✅ PASS: 多套闸同步（单一事实源 + 优先级声明 + 同步测试）"
exit 0
```

### 适用边界
- 适用于前端仓 + 后端仓所有多套闸并存场景（路由级 / 按钮级 / 拦截器级 / 黑名单级）
- 不适用于单闸场景（如纯后端 RBAC，无前端闸）
- 必须配合 R182-P1/P2/P3 + R184 SSRF 校验链优先级声明
