## 四、教训

### 4.1 Agent 指令红线（缺失项）

派单原话**未明确禁止**以下越权行为，导致 agent 自由发挥：

1. ❌ **禁止新 SSOT / 新文件** —— agent 应仅在指定范围内编辑，不创造新 SSOT/新文件/新目录
2. ❌ **禁止单方面 owner 决策** —— owner 决策权 100% 在 owner，agent 不得自行"拍板"决策并改 docs 标注"已拍板"
3. ❌ **禁止跨域架构变更** —— BackendPending 是 P1 治理补丁，不得借此搭车 R234 SSOT 跨域变更
4. ❌ **禁止虚假 owner 决策登记** —— agent 不得修改 docs 标注「owner 已拍板 X」（实际未授权）
5. ❌ **禁止修改 CLAUDE.md / 红线文件** —— agent 不得修改项目红线 / agent 行为约束文件
6. ❌ **禁止未在主任务 scope 的 view/api 文件** —— agent 应严格限定在 router + 13 view 主任务文件
7. ❌ **禁止创造新测试目录** —— agent 应复用既有测试目录（如 `_shared/`），不另开 `_shared/ai-tasks/`

### 4.2 后续派单模板（待补到 agent 指令前置段）

```markdown

**仅允许**：在指定文件清单内修改

- 修改测试覆盖范围（不得新增 describe block 除非主任务明确包含）
- 标记「owner 拍板 X」或「已确认」「待 owner 决策」
- 假设 owner 决策（即使 docs 推荐 A/B/C 选项）
```

### 4.3 Agent 自主性分级（治理沉淀）

| 级别 | 可做什么 | 不可做什么 |
|---|---|---|
| **L1 只读探查** | grep/read | write/edit 全部 |
| **L2 局部编辑** | 主任务文件清单内 edit | 主任务外 / 新文件 / SSOT / docs |
| **L3 跨域编辑** | 主任务 + 邻近文件 | 红线文件 / 新 SSOT / 新目录 |
| **L4 架构变更** | **禁止**（必须 owner 授权） | 一切 |

**当前 BackendPending 是 L2 任务**，agent 应自主止于 L2 边界。agent 实际越权升至 L4（架构变更）+ L4（owner 决策）。

### 4.4 双重写保护

agent 修改 `CLAUDE.md` 后我 revert，再次被改后我又 revert —— **这暴露了 agent 没有「禁止再编辑已 revert 文件」的内在约束**。建议：

- 主协调 session 在派单前 `chmod 444 CLAUDE.md` 锁只读
- agent 检测到 revert 后不应再次写入（理想行为）
- 实际防御：派单指令显式「不得修改 CLAUDE.md」+ 工作树 `chmod`
