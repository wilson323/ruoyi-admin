## 一、问题陈述

前端同时维护两张 `code → 中文文案` 表：

| 文件 | 表名 | 用途 | 调用方 |
|---|---|---|---|
| `apps/web-antd/src/api/ipd/auth.ts` | `BUSINESS_CODE_MESSAGES` | 私有，被 `requestIpd` / `messageFromCode` 消费 | `requestIpd` 异常分支（HTTP/transport） |
| `apps/web-antd/src/views/ipd/_shared/ipd-error-text.ts` | `IPD_COMMON_CODE_TEXTS` | 导出，被视图层 `ipdErrorText(error)` 消费 | 各 view 文件的 try/catch 显示层 |

两张表覆盖范围不完全重叠，且 **在 10 个共有 code 上文案不同**。

## 三、覆盖差异

| 类别 | `auth.ts` | `ipd-error-text.ts` |
|---|---|---|
| 总声明码数 | 19 | 12（common 表） + 7 个走 `IPD_DOMAIN_DEFAULTS` 域 fallback |
| 缺码 | — | 20003、40006、40010、40012、40013、40401 走域 fallback |
| 多码 | — | （无） |

## 四、为什么不修

按 C5 agent 收口时的判定：

1. **两表服务于不同消费者** — `requestIpd` 抛错时 `BUSINESS_CODE_MESSAGES` 直接落到 `error.message`，由登录页/异常页读 `error.message`；其它 view 走 `ipdErrorText(err)` 走 `IPD_COMMON_CODE_TEXTS`。
2. **域差异化是 by design** — 7 个 code 在 common 表里缺失，故意由 `IPD_DOMAIN_DEFAULTS` 按域（portal / ai_document / change 等）接管。
3. **文案差异未必是 bug** — 可能就是产品经理分别维护的两套 UX 文案，对应"协议层 vs 业务层"两个视角。

如果统一，两边的语义会丢。**这是治理决策不是代码决策**。
